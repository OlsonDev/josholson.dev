# TypeScript

`mise web:lint` runs the format check (`bun fmt`) and `bun lint`. `bun fmt` is the one formatter: it formats `.ts`, `.svelte`, `.css`, and `.json` alike, and it sorts imports (`sortImports` in `web/bunfig.toml`). The rules are in `web/bunfig.toml`, and `bun lint` reads them for `.svelte` files only because `web/.oxlintrc.json` exists (empty on purpose; delete it when `bun lint` lints Svelte without it, [oven-sh/bun#45163](https://github.com/oven-sh/bun/issues/45163)).

- `Date` is banned, as a value, as a type, and through `globalThis` or `window`: use Temporal (`Temporal.Instant` for an instant). Like `BannedSymbols.txt` for C#, the message says what to use instead, and a new ban goes in `web/bunfig.toml`.
- Await every promise, or return it. `typescript/no-floating-promises` and `no-misused-promises` enforce it, but they need types, so they do not run on `.svelte` files: keep API calls in `.ts` modules and `load` functions.
- Call the API through the generated client (`import { tag } from '#lib/api/index.ts'`, `tag.get({ tagId }, options?)`), never with `fetch`. The generator calls the runtime's `http.get` and its siblings, never app code. A call takes its path and query parameters as one object, then the body, then `CallOptions` (`signal`, `headers`, `dedupe`, `onError`: `false`, or a handler whose result is the call's, as in `tag.getAll(nullOnApiError)`; never a `try`/`catch` or `.catch` to repeat for a call that can fail), and leaves out what the action does not have. A failure is thrown as an `ApiError` (`status`, `problem`, `fieldErrors` keyed by field for a form, `formErrors` for what is about the request as a whole, `messages` for a toast, `traceId`; `status` is 0 when the network failed), and an abort rejects with the signal's reason. Identical calls in flight at once share one request, and in development `onDuplicate` warns when a component asks twice: fix the component, not the warning ([ADR 0043, the generated API client](../../docs/adr/0043-generated-api-client.md)).
- A call from a server `load` goes in `+page.server.ts`, so what it fetched is serialized with the page and not fetched again in the browser. The client is configured in the `init` hooks, and a call made before they finish fails.
- An instant is a `Temporal.Instant`, converted as the response arrives, and `Temporal` is polyfilled where it is missing (`ensureTemporal`). Unit tests are `*.test.ts` beside the code, run by `bun test`, and a test builds what it needs in the test: a fake `fetch` for the client.
- Imports are sorted by the formatter, never by hand: packages (`svelte`, `@sveltejs/kit`, `$app/...`) first, then `#lib/...`, then relative paths, a blank line between those groups, each sorted by path, with the names inside `{ }` sorted too. A comment directly above the first import is taken for that import's own and moves with it, so a banner at the top of a generated file is followed by a blank line. It runs on save in VS Code (the Custom Local Formatters extension runs `bun fmt --stdin-filepath`, from `.vscode/settings.json`), by `mise web:format`, and in the pre-commit hook, which refuses a commit whose staged web files it would change (it judges the staged content, so a partly staged file is checked as committed).
- `for...of`, not `Array#forEach` (like C#'s `foreach`), and `===`.
- Only the `<script>` of a `.svelte` file is linted. Markup is not.
- The interface is shadcn-svelte components on Tailwind CSS ([ADR 0045, Tailwind CSS and shadcn-svelte](../../docs/adr/0045-tailwind-css-and-shadcn-svelte.md)). Add one with `mise web:ui:add <component>` (never the CLI alone, which leaves `.js` imports), import it as `#lib/components/ui/<name>/index.ts`, and style with Tailwind classes, not a `<style>` block, except for what utilities cannot say. `src/lib/components/ui` is shadcn-svelte's and ours to edit, but only to fix a bug: an edit is its own commit, with a first comment `// Customized from shadcn-svelte: <why>`, and `mise web:ui:diff` shows how the folder differs from what the CLI copies in today (update workflow in the ADR). Our own components go in `src/lib/components`, outside `ui`, and wrap a `ui` component rather than edit it where they can. A tag's color is a stored palette name, so map it to class names that appear in the source, never `bg-${color}-500`.
- Never edit `src/lib/api/schema.ts` or the generated modules beside it (`tag.ts`, `index.ts`, ...), which `mise api:openapi` writes (`schema.ts` is excluded from linting, the rest is linted like any other code). `src/lib/api/runtime/` is ours to edit.
- A disable comment names the rule and says why (`// eslint-disable-next-line <rule> -- <reason>`), and `bun lint` reads ESLint's syntax.
- Bun has no `bunx` here: write `bun x`.
