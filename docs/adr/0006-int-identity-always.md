# ADR 0006: `INT GENERATED ALWAYS` keys

- Status: Accepted
- Date: 2026-10-21

## Context

We prefer identity columns over UUIDs, ULIDs, and GUIDs for performance, and want tests to assert on IDs.

## Decision

Primary keys are `INT NOT NULL GENERATED ALWAYS AS IDENTITY`. An explicit insert needs `OVERRIDING SYSTEM VALUE` in that statement. This is similar to SQL Server's `IDENTITY_INSERT`, but per statement.

## Alternatives considered

- `GENERATED BY DEFAULT`: accepts explicit values with no ceremony, but accidental explicit inserts go unnoticed.
- `BIGINT`: not needed at this scale.

## Consequences

- Neither form advances the sequence on an explicit insert (SQL Server does move its seed). Loaders must call `setval` afterwards.
- Seed loading uses `OVERRIDING SYSTEM VALUE`.
