# ADR 0043: A generated API client of standalone functions, with a configured `fetch`, shared in-flight requests, and instants as Temporal

- Status: Accepted
- Date: 2026-11-17

## Context

[ADR 0042 (the OpenAPI document and enum numbers)](0042-openapi-contract-and-enum-numbers.md) generates the types of what the web sends and receives. Calling the API was still hand-written (`getTags`), with its URL, its error handling, and its `Tag` type written again for each call.

A client has several jobs it can take on, and each has a cost. One class that every component imports whole cannot have any of it left out of a chunk. A result cache with a TTL needs invalidation, which is a second source of truth about what is fresh. A global loading indicator needs every call to opt out when it should not show. This site renders on the server, SvelteKit already reruns a page's `load` when told to, and the admin area is one user, so a client-side cache and a global indicator solve problems it does not have. What does earn its place is sharing a request that several components ask for at once, which saves work and also finds the component that re-runs when it should not.

## Decision

- **A module per controller, a function per action** (`web/src/lib/api/tag.ts`, ...), generated by `web/scripts/generate-api-client.ts` from the OpenAPI document and committed with `schema.ts`. `index.ts` re-exports each module as a namespace, so a call reads `tag.get({ tagId })` (`import { tag } from '#lib/api/index.ts'`). The functions are standalone, not properties of an object, so a bundler drops the ones a route does not call: a route that calls `tag.get` ships `tag.get` (a build of exactly that was 533 bytes, with none of the other 17 operations anywhere in the client output), and an admin-only call is only in admin routes' chunks. A shared runtime is its own small chunk.
- **The shape of a call:** the path and query parameters as one object (they are simple values, never JSON), then the body, then `CallOptions`, each left out when the action has none: `tag.getAll(options?)`, `tag.get({ tagId }, options?)`, `tag.update({ tagId }, body, options?)`. The names are the controller and the action, from the operation IDs the API gives (`controller.action`, in [ADR 0042 (the OpenAPI document and enum numbers)](0042-openapi-contract-and-enum-numbers.md)); an action whose name is a reserved word or would shadow a parameter (`delete`, `options`) is declared with a `$` and exported under its own name. A create (`201`) returns `{ location }`, since the `Location` is the point of it. What a generated function calls is the runtime's function for its method (`http.get`, `http.post`, ..., a namespace, so an action named `get` or `delete` does not collide), with the options first (every function has them), then the operation's name, its route (`route` over a template literal, which encodes each path parameter as a segment, so no route is parsed at run time), and only then what the method takes: a body, the shape of a response with instants in it, a query. A `GET` has no body, so it has no argument for one, and an argument is passed as `undefined` only to reach one after it. There is no argument for what comes back: a `201` is `{ location }`, a success with nothing in it is `undefined`, and anything else is JSON, and a call that must deviate gets an option in `CallOptions`, not a parameter. The hover documentation is the C# XML comments: the summary, remarks, each parameter, the success response, and every error status as `@throws {ApiError}`.
- **The runtime is hand-written** (`web/src/lib/api/runtime/`), imports nothing from SvelteKit, and is unit tested with `bun test`. The generator and the runtime have nothing specific to this site in them, so they can move to a package when a second project wants them.
- **`fetch` is configured, not passed.** `configureApi({ baseUrl, fetch, onError, onDuplicate })` runs once per context, in SvelteKit's `init` hooks: on the server `fetch` is `() => getRequestEvent().fetch`, the request's own (`event.fetch`, which SvelteKit creates per request, and which sends what a `load` fetched to the browser with the page instead of fetching it again); in the browser it is the global one; a test passes a fake. It is a function because the server's is only valid during its request, and the runtime asks for it at the moment a call starts, before anything is awaited. There is no default base URL: a call made before `init` has finished (or in a context nobody configured) fails with a message, instead of going to the page's own origin.
- **Failures are thrown as `ApiError`**: the status (`0` when the network failed, with the cause), the operation, the problem details, `fieldErrors` (the `errors` of a `422` or a binding `400`, keyed by JSON name, for a form: the JSON reader's `$.slug` is `slug` there), `formErrors` (what is about the request as a whole: the `""` key the API uses for a rule across fields, and `$`, the JSON reader's key for a body it cannot read), `messages` (all of them in one list, or the one `detail` or `title` when there are no validation errors, for a toast), and the `traceId`. The global `onError` hook sees each one before it is thrown, for what the whole app does (a sign-in redirect on `401`, a toast on a `5xx`). A call can opt out with `onError: false`, or take the error itself with `onError: (error) => ...`, whose result is the call's (the hook does not see it, and the handler throws to let the error go). The common handlers are prebuilt, frozen options (`tag.getAll(nullOnApiError)` is the tags or `null`), so a page does not repeat a `try`/`catch`, and the function's type adds what the handler returns (`Recovered`), so a caller must handle the `null`. An aborted call rejects with the `AbortSignal`'s reason, as `fetch` does, and is not an `ApiError` or the hook's business.
- **A request in flight is shared, for every method.** Identical calls at once (the same operation, URL, headers, and body text) send one request: a call is compared only with the requests in flight for its own operation, by the text that is sent anyway, so nothing is built to compare and most calls cost one map lookup. A body with the same members in another order is another request, which costs a request and nothing else. Each caller parses the shared response text itself, so each owns its result. `POST` is included: the APIs this site will have take filters, sorting, and paging in a body, and calling the same one twice at once is never meant. It is only while in flight; the next call asks again. The map is per `fetch`, so on the server one request's calls are never another's. A caller that aborts stops waiting, and the request itself stops only when every caller has. `dedupe: false` opts out. In development `onDuplicate` warns with both call stacks, so a component that asks twice is found, and the page that asked five times is not quietly fine.
- **No result cache, no TTL, no invalidation API, no loading indicator.** What is fresh is `load`'s business: SvelteKit's `invalidate` reruns it. Speed on a public page is HTTP caching (`Cache-Control` and `ETag` from the API), which also helps anything that is not this client. A page shows its own loading state, and `navigating` covers navigation.
- **Instants are `Temporal.Instant`, converted as the response arrives.** The types generator emits `Temporal.Instant` for a `date-time` (`Date` is banned, [typescript.md](../../.claude/rules/typescript.md)), and a response has to say which of its strings those are, because JSON has no date type and converting everything that looks like one would convert a tag named after a date. That is a shape, built from `instant`, `arrayOf`, and `objectOf`, and typed `Shape<T>` so the compiler ties it to the type it describes. The types generator writes one next to each schema that has an instant in it, with the same name (a type and a value can share one, so `import { PasskeyResponse }` brings both): `export const PasskeyResponse: Shape<PasskeyResponse> = objectOf({ createdUtc: Instant, lastUsedUtc: Instant })`. An array of such a schema has a constant too, `PasskeyResponseList` (`List` is a suffix, not a plural, which would need rules for `Category` and `Person`; the generator fails if a schema already has that name), written when an operation's response or another schema has one, so every array of it shares one. An operation and a schema refer to a constant by name and never build one, so nothing is built per call and no shape can be shadowed by an action's name (every constant is PascalCase, every action is not), and `/*#__PURE__*/` keeps a route that does not call the operation from shipping it. The constants are written in an order that puts each after what it refers to and otherwise by name (a topological sort that takes the smallest ready name), so the output depends on the names and nothing else, and a new schema is where its name puts it. A value is converted as it arrives, so it is never half converted. Only an operation with instants passes a shape. A request needs nothing: a `Temporal.Instant` serializes as its ISO text. `Temporal` is native in Chrome, Edge, Firefox, Bun, and Node 26, and not yet in Safari, so `ensureTemporal` loads `temporal-polyfill` (its README says about 19 kB gzipped; it is its own chunk) in the `init` hook only where it is missing. Run in a browser with `Temporal` removed, it was fetched once and parsed an instant to the nanosecond; with `Temporal` native it was never requested. SvelteKit cannot send a `Temporal.Instant` between the server and the browser on its own, so `src/hooks.ts` has a `transport` for it.

## Alternatives considered

- `{ fetch }` in each call's options: it works, and is a reason to read every server `load` twice.
- A singleton `fetch`: wrong on the server, where each request has its own and the server serves many at once.
- Sharing only `GET`: the filters and paging do not fit in a query string, so the calls that most need it are `POST`.
- An object of every controller (`api.tag.get`), or a library's generated client (`hey-api`, `openapi-fetch`, Orval): the first cannot be tree-shaken, and none of the libraries was found to produce this shape, with path and query as one object, a body, and options last. This was a search, not a trial of each.
- A client-side result cache with a TTL and server-pushed invalidation: kept for if a client-fetched picker needs it, declared on the server (an `x-cache` extension from a C# attribute) and cleared by controller.
- `Date` for instants: millisecond precision, mutable, and the project bans it.

## Consequences

- The generator reads `application/json` only: no uploads, downloads, or `QUERY` (`openapi-typescript` does not know it either), and it refuses, when it generates, an instant inside a type that refers to itself, in a dictionary's values (a shape names members), or in a response that is not a schema or an array of one. It would otherwise leave an instant a string where the type says `Temporal.Instant`. A recursive type would get a lazy reference on the member that closes the cycle, and a list could get siblings (`Set`, `Map`) if a need appears. A new need extends the generator, and the generator fails loudly until it does.
- Data a server `load` returns to the page can carry instants because of the `transport` hook. The two unit tests of it cover the encoding, and nothing yet sends one through a real page.
- Authenticated calls made while rendering on the server would need the visitor's cookie forwarded to the API, which `event.fetch` does not do for another host. The admin pages avoid it by calling from the browser, which has the cookie; the first page that needs it on the server has to solve it.
- Two components that ask for the same thing at once get one request and a warning in development, and in production only the saving, so the bug is not visible there.
- `schema.ts` and the generated modules are committed, nothing checks that they are current, and a change to a controller or payload is followed by `mise api:openapi`.
